# pdmScripts

This set of scripts implements the “pre-prepared database with subsequent mapping” flavour of the *precursor database method* for inflow turbulence generation in Ansys Fluent. It allows generating a three-dimensional transient velocity profile using a precursor (driver) domain and translating it to another domain’s inlet. Read more about the method [here](https://www.sciencedirect.com/science/article/abs/pii/S0167610520301203).

## Foreword

a. The UDF scripts will need to be compiled and loaded into Fluent. This is done via *User-Defined > Compiled*. You can use the built-in compiler.

b. Depending on the duration of the run and the timestep size, the resulting database can be quite large (aim for tens of gigabytes for tens of physical seconds with 1e-4 seconds timestep size). Make sure that you have enough free disk space.

c. In case anything was missed from the instructions in this file, please refer to the messages in the Fluent console and/or comments in the source code, as well as Fluent User Manual. 

Thank you.

## Requirements

- Python 3.10+;
- NumPy 2.2.6+;
- SciPy 1.15.3+.

## Procedure
### 0. Preparations
0.1. Download the scripts from this repository and place them into your project’s working directory.

0.2. In the same directory, create two folders: **tp_pre** and **tp_sim**. They will store the transient profile generated by the precursor domain and the profile adapted to the simulation domain, respectively. 

### 1. Precursor (driver) domain
1.1. Load the precursor domain and come up with a sampling plane location depending on your case. 

1.2. Create a Cell Register, which should only consist of cells adjacent to the sampling plane. 

1.3. Split the Register into a separate Cell Zone using *Domain > Zones > Separate > Cells...* in the ribbon. Then, in the structure tree, expand *Cell Zones* and notice the ID number of the newly created Cell Zone.

1.4. Compile and load the **TP_WriteProfile.c** UDF script. It will remind you to set the `tp-zoneid` integer RP-variable using the following command:
```scheme
   (rp-var-define 'tp-zoneid ZONE-ID 'integer #f)
```
where `ZONE-ID` is the ID number from step 1.3. This is crucial to the procedure and will result in a fatal error if omitted.

1.5. By default, the transient profile files use the `TP` prefix and `6 digits` for timestep precision. You can change that by defining the `tp-prefix` string RP-variable and the `tp-precision` integer RP-variable, respectively.

1.6. Execute the **tpWriteInit** function using *User-Defined > Execute on Demand...* in the ribbon in order to initialise the variables used by the tpWrite scripts.

1.6. Hook the **tpWriteAtEnd** function to the simulation using *User-Defined > Function Hooks... > Execute at End* in the ribbon.

1.7. Now you can run the simulation.

### 2. Profile Interpolation
2.1. Load the simulation domain.

2.2. Compile and load the **TP_GetInletData.c** UDF script. It will remind you to set the `tp-inletid` integer RP-variable using the following command:
```scheme
    (rp-var-define 'tp-inletid INLET-ID 'integer #f)
```
where `INLET-ID` is the ID number of the simulation domain’s inlet. This is crucial to the procedure and will result in a fatal error if omitted.

2.3. Execute the **tpGetInletData** function using *User-Defined > Execute on Demand...* in the ribbon. This will print the mapping of the simulation domain’s inlet to the computer’s processors into the console. 

2.4. Copy this data and save into a separate .csv-file. 

2.5. Now you can run the **TP_Interpolate.py** script and launch the interpolation process. The script will take three arguments: the filename from step 2.4. and the folders from step 0.2. An optional fourth argument may be used to specify custom initial time. 

2.6. Note that the process may take quite a while depending on the database size.

### 3. Simulation domain
3.1. Once the first interpolated file has been created, you can compile and load the **TP_ReadProfile.c** UDF script into the simulation domain. This action will initially set the velocity profile to zero.

3.2. If your profile prefix and timestep precision differ from the default values, specify them by defining the `tp-prefix` and the `tp-precision` RP-variables similarly to step 1.5.

3.3. Execute the **tpReadInit** function by going to *User-Defined > Execute on Demand...* in order to initialise the variables used by the tpRead scripts and load the first transient velocity profile .csv-file.

3.4. Go to the domain’s inlet, choose *Components* for *Velocity Specification Method* and select `udf UX::libname`, `udf UY::libname` and `udf UZ::libname` for *X-Velocity*, *Y-Velocity* and *Z-Velocity*, respectively.

3.5. Make sure that the simulation duration is equal to or less than the database size, and that your timestep size matches the profile’s, since timestep interpolation is not supported at the moment. 

3.6. Finally, hook the **tpReadAtEnd** function by going to *User-Defined > Function Hooks... > Execute at End*. 

3.7. Now you can run the simulation.
